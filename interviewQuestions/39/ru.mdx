Хеш-функции в SQL используются для преобразования входных данных произвольной длины в фиксированную строку определенной длины.
Это преобразование называется **хешированием**, и оно широко применяется для обеспечения безопасности, целостности данных и оптимизации операций сравнения и поиска.

## Основные случаи использования хеш-функций в SQL:

### 1. Хранение паролей

- Вместо хранения паролей в открытом виде, их хранят в виде хешей. Даже при утечке базы данных злоумышленнику придётся подбирать каждый пароль перебором.
- Для паролей используют специальные медленные алгоритмы с солью: `bcrypt`, `scrypt`, `Argon2`. Соль — случайная строка, которую добавляют к паролю перед хешированием, поэтому одинаковые пароли дают разные хеши.
- Обычные `SHA-256` и `SHA-512` для паролей не подходят: они слишком быстрые, и без соли одинаковые пароли дают одинаковые хеши, которые легко подобрать по словарю. Пароли обычно хеширует приложение, а база данных только хранит результат.

### 2. Проверка целостности данных

Хеш-функции позволяют определить, были ли данные изменены. Создавая хеш от исходных данных и сравнивая его с текущим хешем, можно обнаружить изменения.

### 3. Индексирование и оптимизация поиска

Хеш-значения могут использоваться для быстрого сравнения больших объемов данных или создания индексов для ускорения поиска.

### 4. Создание идентификаторов по содержимому

Хеширование помогает генерировать идентификаторы записей на основе их содержимого. При стойкой хеш-функции они практически уникальны, хотя коллизии теоретически возможны.

## Пример использования хеш-функций в SQL:

Проверим, не изменилось ли содержимое документов после сохранения. Пример для MySQL: функция `SHA2(строка, 256)` возвращает хеш в виде 64 шестнадцатеричных символов.

```sql
-- Создаем таблицу документов с хешем содержимого
CREATE TABLE Documents (
    id INT PRIMARY KEY,
    content TEXT NOT NULL,
    content_hash CHAR(64) NOT NULL
);

-- При добавлении документа сохраняем хеш его содержимого
INSERT INTO Documents (id, content, content_hash)
VALUES (1, 'Договор №1', SHA2('Договор №1', 256));

-- Находим документы, содержимое которых изменилось после сохранения хеша
SELECT id FROM Documents
WHERE content_hash <> SHA2(content, 256);
```

В PostgreSQL тот же хеш вычисляет выражение `encode(sha256(convert_to(content, 'UTF8')), 'hex')`.

## Рекомендации и особенности

### Выбор хеш-функции

- Для проверки целостности и сравнения данных отдавайте предпочтение `SHA-256` или `SHA-512`.
- Избегайте `MD5` и `SHA1` там, где важна безопасность: для них известны способы подобрать коллизии.
- Для паролей используйте `bcrypt`, `scrypt` или `Argon2` с солью.

### Формат хранения

Хеш можно хранить в бинарном виде (`VARBINARY` в MySQL, `BYTEA` в PostgreSQL): он занимает вдвое меньше места, чем запись шестнадцатеричными символами.

### Необратимость хеша

Помните, что хеширование является односторонней функцией; исходные данные невозможно восстановить из хеша.
