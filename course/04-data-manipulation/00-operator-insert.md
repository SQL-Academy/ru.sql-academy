# Добавление данных, оператор INSERT

До сих пор мы только читали данные. Но данные в таблицах не стоят на месте: появляются новые товары, клиенты, заказы, и для каждого в таблицу нужно добавить строку. Для этого есть оператор `INSERT`.

## Общая структура запроса с оператором INSERT

```sql
INSERT INTO имя_таблицы [(поле_таблицы [, ...])]
{ VALUES (значение [, ...]) [, ...] | select_выражение };
```

- `имя_таблицы` — таблица, в которую добавляются записи.
- `поле_таблицы` (необязательный) — столбцы, которые получат значения. Без списка значения передаются для всех столбцов
  таблицы.
- `значение` — значение для столбца: число, строка, выражение или `NULL`. Значения идут в том же
  порядке, что и столбцы. Каждые скобки — одна строка, несколько строк перечисляются
  через запятую.
- `select_выражение` (подзапрос) — запрос `SELECT`, строки результата которого добавляются в таблицу. Он должен
  возвращать столько же столбцов, сколько их перечислено.

Значения передают списком после `VALUES` или получают запросом `SELECT`.

## Перечисление полей и соответствие значениям

Можно явно указать, в какие поля таблицы попадут данные. Для этого имена полей перечисляют в круглых скобках после названия таблицы:

```sql
INSERT INTO имя_таблицы (поле_таблицы [, ...])
VALUES (значение [, ...]);
```

- `имя_таблицы` — таблица, в которую добавляются записи.
- `поле_таблицы` — столбец, в который записывается значение. Столбцы перечисляются через запятую в любом
  порядке.
- `значение` — значение для столбца, который стоит на той же позиции в списке полей.

**Важные правила:**

- Порядок значений в `VALUES` должен строго соответствовать порядку полей в перечислении
- Количество значений должно совпадать с количеством указанных полей
- Если поле не указано в перечислении, оно получит значение по умолчанию (если оно задано) или `NULL` (если поле допускает `NULL`)

Например, если таблица `Goods` имеет поля `good_id`, `good_name` и `type`, то следующие запросы эквивалентны:

```sql
-- Явное указание полей
INSERT INTO Goods (good_id, good_name, type)
VALUES (20, 'Table', 8);

-- Изменённый порядок полей - значения меняются соответственно
INSERT INTO Goods (good_name, type, good_id)
VALUES ('Table', 8, 20);
```

Если не указывать список полей, то значения должны быть перечислены для **всех** полей таблицы в том порядке, в котором они были определены при создании таблицы:

```sql
INSERT INTO Goods
VALUES (20, 'Table', 8);
```

> Рекомендуется всегда явно указывать список полей.
> Это делает код более читаемым, защищает от ошибок при изменении структуры таблицы и позволяет вставлять значения только в нужные поля.

## Различия между синтаксисами INSERT

Добавим в справочник товаров стол. Сделать это можно двумя способами.

ER-диаграмма базы данных Family: [открыть на SQL Academy](https://sql-academy.org/ru/guide/operator-insert).

### INSERT INTO ... VALUES

Значения перечисляются в скобках после `VALUES`. Этот способ подходит, когда данные **известны заранее**:

```sql
INSERT INTO Goods (good_id, good_name, type)
VALUES (20, 'Table', 8);
```

Так можно добавить и несколько строк за раз, каждую в своих скобках:

```sql
INSERT INTO Goods (good_id, good_name, type)
VALUES
    (20, 'Table', 8),
    (21, 'Chair', 8),
    (22, 'Lamp', 8);
```

### INSERT INTO ... SELECT

Значения возвращает запрос `SELECT`. Его можно записать и без таблицы — тогда он просто вернёт перечисленные значения:

```sql
INSERT INTO Goods (good_id, good_name, type)
SELECT 20, 'Table', 8;
```

Оба способа добавляют одну и ту же строку:

| good_id | good_name            | type  |
| ------- | -------------------- | ----- |
| 1       | apartment fee        | 1     |
| 2       | phone fee            | 1     |
| 3       | bread                | 2     |
| 4       | milk                 | 2     |
| 5       | red caviar           | 3     |
| 6       | cinema               | 4     |
| 7       | black caviar         | 3     |
| 8       | cough tablets        | 5     |
| 9       | potato               | 2     |
| 10      | pineapples           | 3     |
| 11      | television           | 8     |
| 12      | vacuum cleaner       | 8     |
| 13      | jacket               | 7     |
| 14      | fur coat             | 7     |
| 15      | music school fee     | 6     |
| 16      | english school fee   | 6     |
| 17      | airsoft game session | 4     |
| 18      | netflix subscription | 4     |
| **20**  | **Table**            | **8** |

Но чаще `INSERT ... SELECT` нужен, когда данные **берутся из базы**: так копируют существующие строки или вставляют результаты вычислений. Например, продублируем все продукты питания под новыми номерами:

```sql
INSERT INTO Goods (good_id, good_name, type)
SELECT good_id + 100, good_name, type
FROM Goods
WHERE type = 2;
```

## Первичный ключ при добавлении новой записи

Значение первичного ключа в таблице не может повторяться: попытка вставить существующее закончится ошибкой.

Какой номер свободен? Первое, что приходит в голову, — взять наибольший и прибавить единицу:

```sql
INSERT INTO Goods SELECT MAX(good_id) + 1, 'Table', 8 FROM Goods;
```

Способ работает, но ненадёжен. Если два таких запроса выполнятся одновременно, они могут получить один и тот же номер, и один из них завершится ошибкой. Кроме того, способ подходит только для числовых ключей и может выдать номер, который раньше принадлежал удалённой записи. Если на этот номер где-то ссылаются старые данные, они окажутся связаны с новой строкой 💥. Поэтому в реальных проектах номер выдаёт сама база данных.

## Автоматическая генерация первичного ключа

**MySQL**

Первичный ключ можно генерировать автоматически: для этого столбцу `good_id` задают атрибут `AUTO_INCREMENT`.
Тогда при добавлении записи в `good_id` достаточно передать `NULL` или `0` — поле само получит следующее значение счётчика: на единицу больше самого большого из уже использованных.

```sql
CREATE TABLE Goods (
	good_id INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
	good_name VARCHAR(255),
	type INT
);
```

```sql
INSERT INTO Goods VALUES (NULL, 'Table', 8);
```

**PostgreSQL**

Уникальный идентификатор можно генерировать автоматически с помощью типов `SMALLSERIAL`, `SERIAL` и `BIGSERIAL`.
Это не настоящие типы, а сокращённая запись: столбец с таким типом получается целочисленным и сам увеличивается при добавлении новой записи.

```sql
CREATE TABLE Goods (
	good_id SERIAL PRIMARY KEY,
	good_name VARCHAR(255),
	type INT
);
```

```sql
INSERT INTO Goods (good_name, type) VALUES ('Table', 8);
```

## Проверьте себя

В таблице `Goods` уже есть товар с `good_id = 3`, а поле `good_id` — первичный ключ. Что произойдёт при выполнении запроса?

```sql
INSERT INTO Goods (good_id, good_name, type)
VALUES (3, 'chair', 8);
```

1. В таблице появятся две строки с good_id = 3 — Первичный ключ уникален: двух строк с одинаковым значением ключа в одной таблице быть не может.

2. Строка с good_id = 3 заменится новой — Обычный INSERT только добавляет строки и не меняет уже существующие. Для изменения записей есть оператор UPDATE.

3. **Правильный ответ:** Запрос завершится ошибкой — Значение первичного ключа 3 уже занято, поэтому СУБД откажется добавлять строку и сообщит о повторяющемся ключе.
